# Запись вебинара — настольное приложение

Версия 2.2.1 — отдельная программа с собственным окном вебинара и автообновлением. Chrome, расширения,
Node.js и Python на компьютере пользователя не нужны.

## Запуск готовой программы

Windows 10/11 x64: на [странице выпусков](https://github.com/BomBilka1/webinar-recorder/releases/latest)
скачайте `WebinarRecorder-Setup-2.2.1-x64.exe` и установите программу.
При следующих выпусках имя установщика содержит новый номер версии.
Chrome, Node.js и Python устанавливать не нужно.

1. В «Что записывать» выберите «Окно приложения» или «Весь экран».
2. Выберите окно/монитор по миниатюре либо из списка. Для новых окон нажмите ↻.
   В режиме экрана каждый подключённый монитор выбирается отдельно.
3. При необходимости включите «Звук всей системы» (Windows).
4. Нажмите «Начать запись» и выберите файл WebM.
5. В конце нажмите «Остановить и сохранить», дождитесь подтверждения.

Для вебинара внутри программы выберите соответствующий режим, вставьте ссылку,
войдите на сайт и включите воспроизведение. Такой источник продолжает записываться
при сворачивании встроенного окна. Для сторонних приложений это зависит от самого
приложения. Закрытое окно нужно выбрать заново: программа не заменяет его другим
источником автоматически.

Подробная инструкция: [USER_GUIDE.txt](USER_GUIDE.txt).

## Возможности

- Видео и звук конкретного встроенного окна вебинара, независимо от перекрытия
  другими окнами и сворачивания.
- Отдельные режимы «Окно приложения» и «Весь экран», миниатюры и названия окон,
  выбор монитора и обновление списка. В Windows записывается звук всей системы,
  а не исключительно выбранного приложения.
- Пауза/продолжение, таймер, размер файла, выбор качества.
- Запись на диск частями с ограничением очереди в памяти.
- Длительность и индекс перемотки в сохранённом WebM: формируются после остановки
  без перекодирования. На время сохранения требуется место для второй копии записи.
  Старые записи автоматически не изменяются.
- Незавершённая запись остаётся в `.partial`; после успешного завершения
  переименовывается в `.webm`. Готовый существующий файл заменяется только
  после успешного завершения новой записи.
- Значок в трее, запрос предотвращения автоматического сна, защита от случайного
  закрытия во время записи.
- Вход в вебинар сохраняется в отдельном профиле приложения.
- Проверка и загрузка новых версий из GitHub Releases; установка по кнопке после
  завершения записи. Состояние обновления и номер версии отображаются в программе.

## Автообновление

Установленная Windows-версия проверяет обновления через 15 секунд после запуска,
затем раз в 6 часов. Есть ручная кнопка «Проверить обновления». Новая версия
загружается автоматически; кнопка «Установить и перезапустить» запускает установщик.
Во время записи, выбора файла и сохранения установка заблокирована. Программа
не устанавливает обновление автоматически при закрытии. Проверка/загрузка,
отложенная из-за записи, продолжается после сохранения файла.

Выпуски берутся из публичного `BomBilka1/webinar-recorder`, без токена на компьютере
пользователя. Проверку SHA512 загруженного файла выполняет `electron-updater`.
Сертификат издателя пока не настроен. Предварительные версии и откат на старую
версию отключены. Ошибка сети не мешает записи; проверку можно повторить.

Ранее отправленную переносимую версию 2.0 нужно один раз заменить установкой
через Setup.exe. У неё нет механизма самостоятельного перехода на 2.1.
ZIP-сборки из Python-скрипта и запуск исходников показывают, что автообновление
недоступно; механизм поддерживается в установленной Windows-версии.

## Ограничения

Запись свёрнутого **стороннего** окна зависит от того, продолжает ли оно рисовать
видео. Основной режим для фоновой записи — окно вебинара внутри программы.
Захват экрана записывает видимую картинку, включая перекрывающие окна.

Некоторые сайты блокируют вход во встроенном браузере; DRM-видео может быть
недоступно. Обход защиты не реализован. Совместимость с конкретной платформой
вебинара нужно проверить короткой пробной записью.

Компьютер должен оставаться включённым; при принудительном сне запись невозможна.
Формат WebM, до 1080p/30 кадров/с; MP4 и монтаж не реализованы. Длительность и
поиск по времени в незавершённых WebM могут определяться проигрывателем не сразу.
Ориентировочный размер — 1,2 или 2,3 ГБ/час в зависимости от качества и содержания.
Сборка не подписана сертификатом издателя.

Встроенный браузер отделён от системного профиля Chrome. Записи никуда не
отправляются. Сам сайт вебинара работает с сетью и сохраняет данные входа,
как в обычном браузере. Не публикуйте профиль и записи вместе с исходниками.

## Разработка

Node.js 22.12+:

```sh
npm ci
npm start
npm test
```

Интеграционная проверка требует ffmpeg/ffprobe и графический дисплей:

```sh
# Linux
xvfb-run -a npm run test:desktop
# Windows с установленным ffmpeg в PATH
npm run test:desktop
```

Тест открывает локальный движущийся вебинар со звуковым сигналом и захватывает
настоящий WebContents через Electron. Он скрывает нативные окна, проверяет изменение
видеокадров в записи, наличие звукового сигнала и паузу/продолжение. Модульные
тесты проверяют порядок и частичные операции записи, ошибку диска, защиту
незавершённого файла и удаление пустого файла. Тесты выбора источников проверяют
разделение окон и мониторов, исключение окна управления, миниатюры и отказ при
закрытии выбранного окна. Тесты обновлений проверяют отсрочку
проверки/загрузки, запрет установки при записи, повторные проверки, ошибку сети
и повторную установку после ошибки.

Дополнительная проверка реального захвата окна и экрана:

```sh
npm run test:capture
```

На Linux ей нужны X11-дисплей и оконный менеджер (например, twm) внутри Xvfb.
Она проверяет выбор по миниатюре, движение видеокадров при захвате окна и экрана,
а также отказ записи закрытого окна без переключения на другой источник.

## Сборка и публикация установщика

На Windows:

```sh
npm ci
npm test
npm run dist:win -- --publish never
```

В `release/` появятся установщик NSIS, `.exe.blockmap` и `latest.yml`.
`electron-builder.cjs` задаёт источник обновлений; GitHub Actions автоматически
подставляет текущий `GITHUB_REPOSITORY`, поэтому форк обновляется из своих выпусков.
При локальной сборке по умолчанию используется `BomBilka1/webinar-recorder`.

GitHub Actions запускается после push в `main`, по тегу `v*` и вручную. После тестов
Windows-установщик собирается и сохраняется в артефактах. Push публикует новый
стабильный выпуск версии из `package.json`; опубликованный выпуск с тем же номером
не заменяется. Тег, если он указан, обязан совпадать с версией программы.
Сначала все файлы загружаются в черновик выпуска; он становится публичным только
после успешной загрузки всех файлов. Обновления поэтому не видят неполный выпуск.
Ручной запуск по умолчанию только собирает: для публикации включите `publish`.

Для следующего выпуска увеличьте `version` в `package.json`, обновите lock-файл
командой `npm install --package-lock-only --ignore-scripts`, затем отправьте
изменения в `main`. Workflow использует штатный `GITHUB_TOKEN` только на шаге
публикации. Отдельный PAT для сборок не нужен и в приложение не встраивается.
Подписание сертификатом и проверка обновления между двумя Windows-установками
нуждаются в отдельной среде Windows.

Основы механизма: [electron-updater](https://www.electron.build/v26/docs/features/auto-update/).

## Сборка переносимой программы

Python 3.10+, без сторонних Python-библиотек:

```sh
python3 scripts/package.py --platform win32
python3 scripts/package.py --platform linux
```

Скрипт загружает закреплённую версию официального Electron, сверяет SHA256 с
файлом релиза и создаёт ZIP с программой. В сборку попадают только `desktop/`,
необходимые поля `package.json`, инструкция и Electron с его лицензиями.
Профили, записи, `.git`, тесты, `node_modules` и настройки окружения не включаются.
На Windows запускайте скрипт командой `python` вместо `python3`.

Для передачи через Telegram стандартным ботом большой ZIP можно разбить:

```sh
python3 scripts/split_delivery.py dist/WebinarRecorder-2.2.1-win32-x64.zip --out delivery
```

Получатель сохраняет все четыре части и `START-WINDOWS.cmd` в одну папку и
запускает CMD. Он объединяет части, проверяет SHA256, распаковывает ZIP средствами
PowerShell и запускает EXE. Административные права и загрузка из интернета не нужны.

Этот дополнительный способ создаёт переносимые Windows/Linux ZIP без
автообновления. Основной выпуск — Windows-установщик NSIS через GitHub Actions.

Техническая основа: [захват WebFrameMain через Electron](https://www.electronjs.org/docs/latest/api/session#sessetdisplaymediarequesthandlerhandler-opts),
[управление фоновой отрисовкой](https://www.electronjs.org/docs/latest/api/browser-window).
Пока встроенное окно скрыто, программа дополнительно запрашивает небольшой
снимок страницы через `capturePage`, поддерживая обновление кадров композитора.

Предыдущая версия расширения сохранена отдельно в `legacy-extension/`.
